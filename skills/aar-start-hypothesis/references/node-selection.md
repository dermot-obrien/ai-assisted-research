# Node selection (index first)

Before starting any research work, use the node index for O(1) lookup of actionable nodes
rather than scanning the whole DAG.

1. Read `research.yaml` to locate `node_index_path`, conventionally `research/node-index.yaml`.
2. Read the node index and inspect the `ready` list.
3. If `ready` is non-empty, take the first node, or let the user choose from the list.
4. If the index is missing, or `generated_at` is more than 7 days old, fall back to scanning
   the full `hypothesis-dag.yaml`, then regenerate the index afterwards.

The index is regenerated by `/aar-housekeep`, `/aar-sync-research-result` and
`/aar-update-lineage`.

## What the lists mean

| List | Contains |
|------|----------|
| `ready` | `pending` nodes whose parent is `completed`, `validated` or `ineffective` |
| `active` | nodes at `in_progress` or `partially_tested` |
| `framed` | nodes at `framed`: designed, not yet executing |
| `blocked` | `pending` nodes whose parent is still unresolved, with the `blocked_by` chain |

A node in `blocked` can still be worked, but warn the user about the unresolved parents first
and get confirmation. A node absent from the index altogether means the index is stale, not
that the node does not exist.
